# Agent-orchestration landscape (survey for herdr-desktop)

Research, not a design. Date of every fetch: **2026-11-07** (accessed 2026-11-07 for every link below unless a line says otherwise). Written for the owner and for the sibling spec [context-switching.md](context-switching.md).

**How it was made.** Five read-only research workers each surveyed a slice with primary sources (vendor docs and changelogs, repos, issue trackers, HN threads read through the Algolia API), and the author added herdr itself and re-fetched seven load-bearing claims, marked ✓ below. `UNVERIFIED` = not fetched or only seen as a search snippet or an issue title. No screenshots or videos were viewed: every UX description is from docs text. Reddit is blocked for direct fetch (HTTP 403); only about nine threads were read through `.rss`, so Reddit evidence is thin. Issue counts and reaction numbers are as the GitHub API or page showed on that day and will drift.

**This repo today (read from the files, not from memory).** Project-grouped home with a `Needs you` inbox, answer dock (two-step risky answers, re-read-and-digest before sending), triage, bulk bar, `mod+j` next-attention, native ACP chat tab with permission dock, queue with `Take back`, `Past sessions`, observed `Show chat` for terminal panes, terminal mirror with capture mode, dock with splits, safe-action desktop notifications, ssh machines, command palette of actions only, a status bar with `Context N%` ([DESIGN.md](../../DESIGN.md), [design/board.md](../../design/board.md), [docs/PARITY.md](../PARITY.md), [docs/ALERTS.md](../ALERTS.md), [docs/ACP.md](../ACP.md)). Not present: worktree create/remove, a review pane over an agent's changes, checkpoints/rewind, plan-usage meters, automations, handoff, transcript export, unread marks, PR/CI chips, per-project instruction editing, agents/sessions in the palette (being specified in [context-switching.md](context-switching.md)).

## 1. Ten findings that matter

1. **The category moved in a year from "terminal multiplexer for agents" to "agent command center".** Every major vendor now ships an agent-first surface: Codex app "a command center for agents" ([OpenAI 2026-02-02](https://openai.com/index/introducing-the-codex-app/)), Cursor 3 Agents Window ([blog](https://cursor.com/blog/cursor-3)), GitHub Agent HQ mission control ([blog](https://github.blog/news-insights/company-news/welcome-home-agents)), Claude Code `claude agents` ([agent view](https://code.claude.com/docs/en/agent-view)), Zed Threads Sidebar ([parallel agents](https://zed.dev/docs/ai/parallel-agents.md)), JetBrains Air ([blog](https://blog.jetbrains.com/ai/2026/10/air-in-ides-eap/)), Devin Desktop Agent Command Center ([docs](https://docs.devin.ai/desktop/agent-command-center.md)), Kiro Agent Focus Mode ([docs](https://kiro.dev/docs/ide/experimental/focus-mode.md)).
2. **The state vocabulary has converged and ours matches it.** Claude agent view groups `Ready for review / Needs input / Working / Completed` ✓; Copilot app project overview groups `Needs input / Open / Working / Done` ✓ ([docs](https://docs.github.com/en/copilot/how-tos/github-copilot-app/working-with-projects)); Factory `Waiting on you / Working / Idle` ([steer](https://docs.factory.com/workstreams/steer.md)); Codex Pet `needs input > blocked > ready > running` ([commands](https://learn.chatgpt.com/docs/reference/commands)). Our `Needs you / To review / Working / Idle` is the same set.
3. **Human attention, not agent count, is the limit.** Practitioners converge on 2 to 4 supervised threads; beyond that people rubber-stamp ([Osmani 2026-04-07](https://addyosmani.com/blog/cognitive-parallel-agents/), [r/ClaudeCode thread 2026-06](https://www.reddit.com/r/ClaudeCode/comments/1twkch3/how_many_cc_sessions_do_you_run_concurrently), [Willison 2025-10-05](https://simonwillison.net/2025/Oct/5/parallel-coding-agents/)). A home built on "what needs a decision now" (ours) beats a grid of sessions.
4. **Review is the weakest layer everywhere, and the most-voted request is "line comments in the diff that go to the agent".** Zed [#59157](https://github.com/zed-industries/zed/issues/59157) (124 to 156 reactions depending on the day), Codex review pane, Conductor, Orca *Annotate AI Diff*, Warp *Interactive Code Review*, JetBrains Air *Finish & Attach Comments*, Claude desktop diff pane. Cursor shipped an Agents Window without per-change accept/reject and users objected ([forum](https://forum.cursor.com/t/agents-window-is-not-good/157226)). We have no review pane (our biggest functional gap).
5. **Worktree lifecycle is where trust is lost.** Codex managed worktrees never reclaimed, 3.8 GB in five days, 73 GiB on Windows ([#54891](https://github.com/openai/codex/issues/54891)); Vibe Kanban 26 GB in two days and worktrees recreated after deletion ([#765](https://github.com/BloopAI/vibe-kanban/issues/765)); no setup hook ([claude-squad #260](https://github.com/smtg-ai/claude-squad/issues/260), [crystal #39](https://github.com/stravu/crystal/issues/39)). Mitigations that work: keep-N, never delete pinned or in-progress, snapshot before delete ([Codex docs](https://learn.chatgpt.com/docs/environments/git-worktrees)), background create with progress, `.worktreeinclude` and shared dirs ([Orca](https://www.onorca.dev/docs/model/worktrees)).
6. **Native chat plus terminal on the same session is now table stakes.** Orca structured chat covers Claude, Codex, Grok, OpenCode, **Pi, OMP**, Antigravity, with a per-agent Chat/CLI choice ✓ ([docs](https://www.onorca.dev/docs/agents/native-chat)); Paradev chat over ACP incl. Pi ([docs](https://docs.paradev.com/llms.mdx/chat)); Zed Terminal Threads ([docs](https://zed.dev/docs/ai/terminal-threads.md)). Our `Show chat`/`Show terminal` is the same idea, and Orca is the closest competitor (it supports our four agents).
7. **ACP is the integration surface, and its failure modes are shared.** Zed, JetBrains, Devin Desktop, Paradev, Emdash, Goose consume ACP. Recurring ACP-client bugs: session history depends on `session/list`/`load` on both sides ([Zed #51341](https://github.com/zed-industries/zed/issues/51341), [JetBrains LLM-31610](https://youtrack.jetbrains.com/issue/LLM-31610)); permission requests from third-party agents crashing the view (Devin Desktop [3.12.17 changelog](https://docs.devin.ai/desktop/changelog.md)); slow cold start ([Zed #54813](https://github.com/zed-industries/zed/issues/54813)); vendor extensions a generic client must implement (Cursor `cursor/ask_question`, Kiro `_kiro/*`) ([Cursor ACP](https://cursor.com/docs/cli/acp.md), [Kiro ACP](https://kiro.dev/docs/acp.md)).
8. **Vendor churn is brutal; survivors are local and open.** Conductor joins Meta, closed to sign-ups since 2026-11-04, Cloud shuts 2026-11-20 ([announcement](https://www.conductor.build/announcement)); Vibe Kanban company shut down 2026-04-10 ([post](https://www.vibekanban.com/blog/shutdown)); Terragon shut 2026-02-09 ([source](https://raw.githubusercontent.com/terragon-labs/terragon-oss/main/apps/docs/content/docs/resources/shutdown.mdx)); Crystal deprecated for Nimbalyst 2026-02 ([README](https://raw.githubusercontent.com/stravu/crystal/main/README.md)); Jules read-only after 2026-11-11 and shut 2026-12-31 ([changelog](https://jules.google/docs/changelog/)); Windsurf became Devin Desktop 2026-06-02 ([blog](https://devin.ai/blog/windsurf-is-now-devin-desktop)); Superset became Paradev, Mux became Xum.
9. **Upstream herdr now ships its own native desktop app, a new runtime (`herdr-core`, CLI `hc`) and mobile apps.** See section 3; this changes the strategic question more than any feature below.
10. **Accessibility is an unclaimed position.** No GUI wrapper (Conductor, Superset, Emdash, Zed agent panel) had a screen-reader thread in HN or GitHub searches; treated as unknown, not "fine". Claude Code documents a screen-reader mode with flat labelled text and a bell on needs-you ([docs](https://code.claude.com/docs/en/accessibility)); HN shows TUI accessibility is contested ([thread](https://news.ycombinator.com/item?id=48006841)). `[INFERENCE]` A GTK/AT-SPI client can be better here than xterm.js/Electron wrappers.

## 3. Upstream herdr: a strategic change (read first)

All facts from [herdr.dev](https://herdr.dev/), [herdr.dev/core](https://herdr.dev/core/), [herdrdev/herdr-app](https://github.com/herdrdev/herdr-app), its [changelog](https://raw.githubusercontent.com/herdrdev/herdr-app/master/CHANGELOG.md), [command reference](https://raw.githubusercontent.com/herdrdev/herdr-app/master/docs/commands.md) and the [privacy page](https://herdr.dev/privacy/), fetched 2026-11-07 (GitHub API for dates and counts).

- **Two products named herdr.** The terminal app `herdr` (TUI, repo `herdrdev/herdr`, Apache-2.0, 48.8k stars, latest release 0.9.5 on 2026-10-14) is what `herdr-desktop` talks to (protocol 22, NDJSON socket). A **new, separate native desktop app** `herdr-app` (Rust, Apache-2.0, repo created 2026-10-16, v0.1.13 on 2026-11-04, 2.2k stars, 422 open issues) is "built on herdr-core"; the site says outright that the two "don't share agents, so what runs in one doesn't show up in the other".
- **herdr-core (`hc`)** is a terminal runtime that "draws nothing and guesses nothing": status comes from **OSC 7501** (`printf '\e]7501;state=blocked:app=my-agent\e\\'`), an open Program Status Protocol, not screen scraping. `hc schema` prints an OpenRPC API with streams, "a phone app, an editor panel, a Stream Deck" are named as intended clients. Agents start and steer other agents (`hc run --bg codex "... Done: hc send t1"`, `hc send`, `hc wait`, `hc read`). Machines are added over SSH (`hc machine add`, `hc run --on`). **UNVERIFIED:** the OpenRPC schema itself (not fetched) and whether `herdr-desktop`'s `herdr-core` crate could speak it.
- **The app's model:** *space* (one repo, one machine) → *tab* (one task) → panes of terminals or JS "mods"; one agents sidebar across spaces and machines, including helpers started by other agents ("peek" them over a tab, keep as tab); `tab.settle` ("put a tab away: out of the lists, still running; it comes back when an agent in it needs you"); pins and seen-state shared between windows and the phone app; palette lists every command with its key; everything is plain files in `~/.config/herdr-app` plus an `AGENTS.md` so your agent edits the app; sounds `done.mp3` / `request.mp3`; usage telemetry on by default in releases (README, Settings > Privacy to turn off).
- **Official mobile apps exist** (iOS and Android, "talks only to the machines you add, over SSH", per the privacy page; Play listing [dev.herdr.mobile](https://play.google.com/store/apps/details?id=dev.herdr.mobile) lists 1K+ downloads). They are not the tuan3w `herdr-mobile` that this repo's keeper and reducer come from (`docs/ARCHITECTURE.md`).
- **OSC 7501 is spreading:** cmux also accepts it ([README](https://github.com/manaflow-ai/cmux)).
- **What herdr-desktop does that upstream's app does not (from its docs):** native ACP chat with permission dock and question forms; a chat/terminal choice per agent; the answer chips with digest re-read; project-grouped inbox with one count; AT-SPI audited accessibility; GTK-native widgets rather than a custom GPU-drawn window (herdr-app "needs a desktop session and a working Vulkan driver"). **What upstream does that we do not:** it runs the terminals itself (persistence without tmux), layouts as shareable files, mods, `hc` agent-to-agent orchestration, one-line agent status protocol.
- **Decision needed:** see open question 1.

### 4.1 Worktree-per-task orchestrators

**Orca** (MIT, free, v1.4.252 on 2026-11-07, 118k stars; [site](https://www.onorca.dev/), [README](https://github.com/stablyai/orca)). Project → worktree; creating closes the dialog at once and runs `git fetch` + `worktree add` in the background with a progress row, cancel and retry; start-from picker; `orca.yaml worktree.sharedDirectories` (symlink) and `.worktreeinclude` (copy) ([worktrees](https://www.onorca.dev/docs/model/worktrees)). Attention: header bell → exact pane, system notification + sound on working→idle, per-category and per-machine mute, palette rows with live badges, unread bolded not badged ([notifications](https://www.onorca.dev/docs/notifications), [quick open](https://www.onorca.dev/docs/model/quick-open)). `Cmd-J` jump palette: empty query shows six recent chats ranked needs-you → done → idle, order frozen while open, `Cmd/Ctrl-1..6`, `Tab` filters host/project, `Shift-Enter` opens in split, unmatched text offers "Create worktree". Review: **Annotate AI Diff** batches line comments into one prompt ("sending one at a time makes the agent swing back and forth") ([doc](https://www.onorca.dev/docs/review/annotate-ai-diff)). Chat: structured chat with rewind-to-message, queue-or-steer cards, collapsed tool runs, per-turn changed-file summary, context ring, number-key answers ✓ ([doc](https://www.onorca.dev/docs/agents/native-chat)); `orca` CLI and a DAG/worker orchestration layer with `worker_done`/`escalation`/`question` inbox messages ([doc](https://www.onorca.dev/docs/cli/orchestration)). Complaints: no multi-worktree side by side ([#8377](https://github.com/stablyai/orca/issues/8377)), no keyboard jump to next agent needing input ([#12577](https://github.com/stablyai/orca/issues/12577)), notification spam on non-final turns ([#4375](https://github.com/stablyai/orca/issues/4375)), RAM creep ([#10928](https://github.com/stablyai/orca/issues/10928)); 4,435 open issues on the day. Shortcut table UNVERIFIED (docs page 404).

**Conductor** (closed, Mac-only, v0.93.0 2026-11-04; [docs](https://www.conductor.build/docs), [changelog](https://www.conductor.build/changelog.md)). "The workspace is the unit of delegation; the branch and PR are the unit of integration" ([workflow](https://www.conductor.build/docs/concepts/workflow)). Checkpoints revert chat and files to an earlier turn ([0.19.0](https://www.conductor.build/changelog/0.19.0-checkpoints.md)); "Next workspace" jumps between unread/needs-attention chats ([0.36.4](https://www.conductor.build/changelog/0.36.4-next-workspace.md)); diff line comments become composer attachments ([diff viewer](https://www.conductor.build/docs/reference/diff-viewer.md)). Complaints: no public tracker (UNVERIFIED); self-admitted perf fixes (0.7.0, 0.38.x). Winding down by early 2027 ([announcement](https://www.conductor.build/announcement)).

**Paradev, ex-Superset** (MIT, desktop v2.0.5; [docs](https://docs.paradev.com/llms.txt)). Board lanes Idle / Working / Needs attention / Needs review / Merged derived from agent and PR state ([workspaces](https://docs.paradev.com/llms.mdx/workspaces)); "worktrees separate files, they do not sandbox processes"; status only for agents launched inside the app ([agent status](https://docs.paradev.com/llms.mdx/agent-status)); ACP chat for Claude, Codex, OpenCode, Pi ([chat](https://docs.paradev.com/llms.mdx/chat)); rename date UNVERIFIED (secondary). Complaints: prompt-first create flow gives no way to name the branch ([#7168](https://github.com/ParadevAI/Paradev/issues/7168), list only), sign-in required ([#4894](https://github.com/ParadevAI/Paradev/issues/4894), list only).

**Emdash Classic** (Apache-2.0, v1.2.11; [docs](https://emdash.com/llms.txt)). Worktree per task, tmux for persistence, hooks for ~20 agents, internal ACP runtime whose permission broker "never auto-chooses" ([ACP runtime](https://raw.githubusercontent.com/generalaction/emdash/main/agents/architecture/acp-runtime.md)); FTS index lock-ups at 2.5 GB ([#2882](https://github.com/generalaction/emdash/issues/2882)); 2.0 becomes a team product ([blog 2026-11-05](https://emdash.com/blog/whats-next-for-emdash)).

**Vibe Kanban / Terragon / Crystal → Nimbalyst / Sculptor / Claude Squad / Xum.** Sunset, shut, deprecated, research preview (worktree by default now), AGPL tmux TUI, keyboard-first Coder app. Lessons: board demoted → revolt ([VK #2509](https://github.com/BloopAI/vibe-kanban/issues/2509)); worktree GC surprises ([VK #765](https://github.com/BloopAI/vibe-kanban/issues/765)); no setup hook ([claude-squad #260](https://github.com/smtg-ai/claude-squad/issues/260)); cloud-only delegation lost to vendor-native agents (Terragon). Xum's palette defaults to a workspace switcher with `>` for commands ([keybinds](https://xum.cdr.dev/config/keybinds.md)).

### 4.2 First-party agent products

**Claude Code** (CLI v2.1.319 on 2026-11-06; [desktop](https://code.claude.com/docs/en/desktop), [agent view](https://code.claude.com/docs/en/agent-view), [worktrees](https://code.claude.com/docs/en/worktrees), [checkpointing](https://code.claude.com/docs/en/checkpointing), [hooks](https://code.claude.com/docs/en/hooks)). Checkpoints: one per prompt, 100 kept, `/rewind` restores code and/or conversation; Bash-made changes and external edits are not restored. Worktrees under `<repo>/.claude/worktrees/` with `.worktreeinclude`; deletion of a row removes its worktree unless dirty. Cross-session messaging lets one Desktop session list, read and message others. Experimental agent teams: no isolation by default ([doc](https://code.claude.com/docs/en/agent-teams)). Complaints: forced nesting and removed Group-by ([#102129](https://github.com/anthropics/claude-code/issues/102129), read), worktrees split per-project memory ([#34437](https://github.com/anthropics/claude-code/issues/34437), 47 reactions), usage ring default changed from context to 5-hour window ([#91712](https://github.com/anthropics/claude-code/issues/91712)).

**OpenAI Codex, now a mode of the ChatGPT desktop app** (Linux preview; CLI Apache-2.0 `rust-v0.167.0`; [app](https://learn.chatgpt.com/docs/app), [commands](https://learn.chatgpt.com/docs/reference/commands), [worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees), [code review](https://learn.chatgpt.com/docs/code-review), [automations](https://learn.chatgpt.com/docs/automations)). `developers.openai.com/codex/app` now redirects to `learn.chatgpt.com`. `Next chat needing attention` is `Cmd/Ctrl+Alt+A` (Codex only) ✓; recent chats `Cmd+Alt+1–6`; Approve = Enter, Decline = Esc while an approval is open; Activity bell view; floating Pet overlay. Review pane over real Git state with scopes Unstaged / Staged / Commit / Branch / Last turn, hunk-level revert, inline comments back to the chat. **Approve for me** routes approvals to a reviewer agent ([auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review)). ## 5. Patterns

### 5.1 Converged: users now expect these

| Pattern | Evidence | Us |
|---|---|---|
| Sessions grouped by project/repo, state on every row | Orca, Zed, Codex, Amp, Copilot app, Cursor, Air; Warp users ask ([#9875](https://github.com/warpdotdev/warp/issues/9875)) | have it, better than most |

### 5.2 Fashion or unsettled (do not build on yet)

- **Kanban boards.** Paradev derives lanes from state; Vibe Kanban demoted its board and users revolted ([#2509](https://github.com/BloopAI/vibe-kanban/issues/2509)). A stable optional lens at most.
- **Coordinator "Projects" with worker agents** (Cursor, Claude Projects beta, Copilot app, Factory, Devin). Real but preview-grade; Gas Town and ruflo show the failure modes.
- **Cloud sandbox per task.** Terragon dead, Conductor Cloud ending, Jules ending; vendor-native clouds absorb it.
- **Pets, LED indicators, hardware keys** (Codex Pet and Micro, Air Caps Lock LED).
- **Per-turn private checkpoints.** Zed removed them; Kiro, Claude, opencode document their gaps. Lean on git.
- **Auto-approve by a model** (Codex Approve for me, Copilot Assisted, ccmanager, Goose Smart Approval): contested and against our rule.
- **Voice, design mode, embedded browser.** Present in Orca and Factory; no evidence of demand from this audience.

## 7. What not to copy

| Do not | Why | Evidence |
|---|---|---|
| Force a layout, nest sessions or drop a grouping without an opt-out | Most-reacted complaints in three products | Claude #102129, Zed #54545, Cursor 165921, opencode #48882 |
| Make status depend on the agent being launched by the app | Our value is supervising agents that already run | Paradev agent-status doc |
| Auto-approve by a model, or by a timer | Approval fatigue is real, but so is silent approval; our principle stands. Offer scoped allow rules (`allow_always` is already two-step) instead | Codex #50572, Claude #37839, ccmanager auto-approval |
| Deny-one-kills-all behaviour | One denied prompt interrupted five parallel agents | Claude #88216 |
| Per-turn private snapshots | Zed removed them (hangs); blind to shell edits | Zed 1.27.0, Kiro and Claude docs |
| Lock a session read-only while its agent runs | Blocks steering | Devin ACC |
| Reorder lists by latest notification | Breaks position shortcuts | [cmux HN](https://news.ycombinator.com/item?id=47091352); our Orca-style frozen order |
| Sound or colour as the only signal; pets, Caps Lock LED, hardware lights | Accessibility; noise | Codex Pet, Air LED; our DESIGN rule 7 |
| Notify per turn | The top bug class in this category | Orca #4375, Paradev #5259, Zed #53274 |
| Hosted transcripts or an account for remote | Privacy and lock-in; relays raise E2EE questions | Claude Remote Control needs claude.ai login and stores transcripts server-side ([doc](https://code.claude.com/docs/en/remote-control)); [Omnara HN](https://news.ycombinator.com/item?id=46992557); Paradev sign-in #4894 |
| Telemetry on by default | Our principle: local only | herdr-app README (on by default) |
| Swarm orchestrators and state-in-an-issue-tracker | Expensive and fragile | Gas Town #764, ruflo #958 |
| Board as the home | A board demoted by users rebelled; keep status lanes as optional lens | VK #2509 |
| Pin agent CLI versions inside the app | Staleness and lock-in | [Ask HN](https://news.ycombinator.com/item?id=48154390) |
| Electron or xterm.js-style rendering for the chat | Screen-reader gap is the open niche; keep native semantics | section 1 finding 10 |

## 8. Open questions for the owner

1. **Upstream herdr-app and herdr-core.** Do we stay on the TUI's JSON API (protocol 22), add a second backend for `herdr-core` (`hc`, OpenRPC, OSC 7501), or watch? Users of the new app cannot see TUI-started agents and vice versa. This sets the shelf life of the whole repo.
2. **Worktrees.** Own them (create/remove through `worktree.*` and git on each machine), for ACP sessions too, or leave them to herdr and the agents' own flags (`claude --worktree`, Codex)?
3. **Review pane scope.** Git state of the folder (Codex-style, works for any agent, needs git over ssh) or only the agent's own edits (what ACP tool diffs give)? Does it include commit, push, PR?
4. **Auto-approval.** Confirm the stance: never a model or timer; scoped allow rules only.
5. **Steer default.** Enter queues (current) or steers where supported? Whichever, one convention.
6. **Local transcript index** for palette search: allowed to store content on disk (privacy), or titles and last messages only (the palette spec's current answer)?
7. **Automations:** machine-resident (cron plus keeper `start`, works with the window closed) or app-resident (simpler, dies with the window, as Claude's and Codex's local schedules do)?
8. **Usage meters:** show only what ACP agents report, or also read plan usage from each vendor's local credentials (unofficial; Claude #99231 asks for an official endpoint)?
9. **Positioning.** Say it plainly: supervisor for any agent on any machine, native and accessible, no account. Competitors that ship Linux builds today: Orca, Copilot app (AppImage), Claude Desktop (beta apt), Codex (preview), Goose, Zed, Devin Desktop, JetBrains Air.
10. **Mobile.** Keep mobile as the separate tuan3w app, or point users to the official Herdr Mobile where they overlap?
