# The chat tab

`components/session-tab.tsx` (`SessionTab`) and its parts: `session-header.tsx`, `session-transcript.tsx`, `session-item.tsx`, `session-tool.tsx`, `session-plan.tsx`, `session-inspector.tsx`, `subagent-chat.tsx`, `session-composer.tsx`, `session-queue.tsx`, `session-attach.tsx`, `session-signin.tsx`. The rules are in `lib/session.ts` (data and the model), `lib/session-rows.ts` (turns into rows), `lib/session-text.ts` (words), `lib/session-compose.ts` (the message box), `lib/session-inspector.ts` (the inspector) and `lib/session-pictures.ts`; all pure ones have tests. The answer dock, question form, overview and the mode and model pickers are `design/chat-parts.md`. `session-tab.test.tsx` drives it through `session-lab.tsx`, `session-inspector.test.tsx` through `session-inspector-lab.tsx`.

## What it is

The primary way to work with an agent: a conversation, not a terminal. One tab is either a keeper's ACP session (`id` is the keeper's) or a terminal agent read from its log (`id` is `pane:<paneId>`, with `Show terminal` one press away). The tab opens itself (`Sessions.attach` or `Sessions.observe`) and lets go when it closes; a session that cannot be opened says why and offers `Try again`, and `Continue` for one whose agent exited and kept its conversation. Top to bottom: `SessionHeader` (one line: `title · project · branch`; the title is a button that opens the session's facts in a popover, `Session details`; then `Changes` and, for a terminal agent with the terminal tab on (`terminalEnabled`, off by default: `design/pane.md`), `Show terminal`; no state word and no mark, because the sidebar row and the dock say it; the project is the board row's, the branch the last read of git), a banner when the connection is lost (`Reconnect`), one quiet line while the inspector is closed and something runs beside the agent (`ActivityLine`), `SessionPlan`, the conversation, the open request (`AnswerDock` or `SessionQuestion`) and `SessionComposer`, which stands aside while the request shows and comes back, draft kept (`design/chat-parts.md`, "Where it stands").

## The conversation reads like a chat

- **You** are a rounded bubble on the right. Pictures in your message are a row of 72 pt thumbnails under the words (`components/turn-pictures.tsx`), fetched once when the row is drawn (`lib/session-pictures.ts`, cap 16 MiB, at most 8 kept) and shown in place of the agent's own `[Image #n]` placeholders (`withoutPlaceholders`; the placeholders stay when more are named than came); a press opens the lightbox; too large, gone or let go of is a tile of the same height (`Picture too large to show`, `Try again`, `Load`), so the row never changes height. **The agent** is Markdown on the page, never a bubble (`MarkdownText`: lists, tables, links through `openLink`, pictures as chips, and every fence a `CodeBlock`; prose is `text-base` (14 at 1.55), a table is a hairline under each row with no fill or side lines (`TABLE_CLASSES`): highlighted, its language in the corner, `Copy code`, folded past 16 lines; `design/code.md`). Nothing is cut; an agent message is one selectable area (a drag crosses paragraphs, lists, code and tables, in the recycled list cell too), and every finished message has `Copy message`, which copies its whole Markdown. `copyReply` (`mod+shift+y`) copies the last answer and `copyCode` (`mod+shift+c`) the block under the pointer or else the last one of it, from anywhere in the tab, the message box included. A host that dies when a chat is replaced or closed is the allocator preloaded into the process, not the text view: `preload_guard` (`docs/upstream/nsh-selectable-textview-in-list.md`); the `chat-swap` scenario of `make shots` fails if the host dies again.
- **A turn is ranked by consequence, not time.** Always visible: a pending question (the dock), the final answer, and under it the **effects row** (`EffectsRow`, row kind `effects`, after the turn's last item and only once the turn is over): failures first (the call and the last line it printed, in the warning colour, never an exit code the agent did not send), then what happened outside the working tree (`ToolItem.effect`: a glyph by kind and the text, `Pushed to origin/main`), then `Edited 3 files +12 −4`, a button that opens the Changes tab of the session's folder on the files that turn edited (`openChanges` with `edited`; the header's Changes button opens it on everything). Why: the supervisor asks "what did it do" and "can I trust it", and a read-only step must never compete with a push. Everything else (reads, searches, commands, thoughts, and the narration the agent wrote between two calls) is one *group* folded to one muted line (`Read 8 files, ran 4 commands, edited 3 files`: zero counts left out, sentence case, no full stop, never a time); only the turn's last message stays on the page. A press opens the steps, one line each (a failed step also shows its last line in the warning colour); the folded line itself only expands. A path in the final message opens the file (`openLink`, `viewFile`). The group is folded while its turn runs too: the live line says what happens. The person's own choice of open or folded wins, kept by row key. The pure rules are `lib/session-rows.ts` (`buildRows`, tests in `lib/session-rows.test.ts`); the effects of a turn are carried from group to group (`TurnCarry`), so streaming rebuilds the last unit and never reads the turn again.
- **No state is repeated in the conversation.** No state word, no centred `Done in 12s`, no timer on a finished turn: the sidebar glyph already says it, and a finished turn is its final answer. While the agent works, one muted live line at the bottom (`Running pnpm test`, `Editing lib/ask.ts`, `Reading 3 files`, `Thinking` when no call is open; `Quiet for 2m` beside it once nothing has arrived for a minute) says what it is doing now and goes when the turn ends (`liveLine`, `model.working().toolLine`). It carries no timer. Times come from what this window watched; a replayed turn shows none, because inventing one is lying.
- **A call is one muted line, in a box with its neighbours**: a muted verb, what it acted on in the normal colour and monospace (`Created package.json +48 ›`, the `+N` green), a trailing chevron, no icon and no check. Success is silence; a failure is the red word `Failed`, a live call its shape. A run of calls is one hairline box (radius lg, rows split by single hairlines, no card per row): one row of the list (`Row` kind `calls`, the calls with nothing between them) drawn as one view, because a box cannot be cut across the list's rows (per-row borders gave ragged corners and broken joins). The agent's narration between two runs is plain prose, muted, with no rule at its side (a rule reads as a quote), and splits the run in two boxes. A command's line says what it did (`commandSubject`, `lib/tool-subject.ts`): `Ran python3 script` for an inline script or heredoc, `Ran grep export in lib`, `Ran sed on components/x.tsx`, else its first line without heredoc, redirections and chained part; the whole command is in the opened row. A subject too long for the row fades out whole (`Clipped`), never a hard cut, and a hover tooltip carries the whole subject. The live line at the bottom wears the same half ring as a running call and starts at the same left edge as the rows. A press opens the row in place: the whole path as a muted caption, then the edit as a `DiffBlock`, the command when the row had to cut it, the output (a few lines, `Show all N lines`, `N lines not kept`). Nothing is open until pressed. Toolbars (`Wrap`, `Lines`, `Copy`, `Split`, the change arrows) show on hover or focus of their block only and stay named and pressable.
- **A subagent stands outside the fold** as its own bordered line (`SubagentRow`; a call of kind `task`, `subagent` or `agent`), because what it hands back is a result, not a step. A terminal agent's subagents and background tasks are the inspector's (below).
- **Thoughts** are one collapsed line (`Thought for 12s`) inside a group; a press opens them.
- **Notices** are quiet centred lines for the app's own notes (`Earlier messages are no longer kept`). A failed call is not a notice: it is a failure line under the answer, in the failure colour, because it must not be folded away.
- **Earlier messages of a terminal's chat** (`observed.earlier`: `none`, `available`, `loading`, `tooLong`). A chat opens at the end of the agent's log (the last 192 KB); the top of the list is `EarlierRow`. `available` is one ghost `Load earlier messages` button; the person who scrolls within one viewport of the top (or whose list is empty) gets it pressed once per arrival (`createAutoLoad` in `lib/earlier.ts`). `Sessions.loadEarlier` returns at once: Rust reads the log again from its end with a tail 4x wider (up to 64 MB) beside the rows shown, and replaces them in one step when the read is whole, so while it runs the rows stay and the row is one `Loading earlier messages…` line of the same height. Rows keep their `id` and the older ones take smaller ones, so the list holds its place and older rows arrive above those in view (key every row by `id`; never by position). `tooLong` is one muted sentence and no button. Why: the log is the truth and a long chat is days of work; the first read must be fast and the rest on request, never a spinner over the whole chat.
- Text from an agent goes through `visibleText`: direction overrides and control characters become `‹U+202E›`, because a command written backwards reads as another command.
- A kind of row the app does not know is a quiet generic line, never a crash.

## Signing in

An agent can refuse a session until the person signs in (`SessionView.phase` is `authRequired`, `acp.auth` lists the ways). `SessionSignin` then stands in for the conversation, the request docks and the message box, under the same header: a calm full-width card, `<Agent> needs you to sign in`, and one block per way the agent offers.

- **A way the app carries out** is a button named as the agent names it, with the agent's description under it. It calls `Sessions.authenticate` (through the port, `SessionPort.authenticate`); while the agent decides the button is busy and the others wait. When the agent accepts, the session opens and the card goes.
- **A way done in a terminal** (`terminalArgs`) shows the arguments the agent gave, quoted for a shell (`shellLine`) in a `CodeBlock`, `Copy command` and `I did it, try again` (`Sessions.reopen`). The app never runs it, and nothing opens a browser or a terminal by itself. The agent's message does not carry its program name, so the line is the arguments only and the card says to start the agent's program with them.
- **A refusal or failure** is the agent's own words under the buttons, which stay; `I did it, try again` that finds the agent still asking says so. What was said lives in `createSignin` (per chat), because the card is gone while the agent reopens the session and comes back if it still wants a sign-in.
- The keyboard goes to the first button once, when the tab is in front, and back to a button that was busy when the answer arrives.
- **Not here:** a way that needs a URL (`AuthMethodView` has no URL: the card never invents one), and `Sign out` (`AcpView.canLogout` is exposed, the `Sessions` module has no logout call).

## Following the end

The list is bottom aligned and virtual: only the rows near the window exist, each reads its row and keeps no state (what is open lives in the model, by row key). It follows the end while the person is at the end (64 pt counts as at it). Scrolled away it holds still and a pill says what is new: `3 new messages`, `Needs you` while a request waits, else `Jump to latest`. The pill exists only while scrolled up: at the end it would point at where the person already is. Sending a message jumps to the end. PageUp and PageDown scroll a page from anywhere in the tab (also from the message box), Home and End when no text box has the focus. There is no `j`/`k`. Streaming rebuilds the last unit only (`createSessionModel` builds the rows before it once), so a 5,000-row conversation opens at its end and streams without a layout jump.

## The message box

A rounded card one line high at rest (it grows with the text, `design/composer.md`), because a tall empty box takes the room of the conversation. Under the text: `+` (attach), the mode chip and model picker (`session-config.tsx`), and one round button. Its help (keys, what a send will do) is inside the card, not a line outside it. The button is `Send`, `Queue message` while the agent works, and `Stop` while a turn runs with nothing typed; a Stop that just appeared ignores presses for 400 ms so the second press of a double press on Send cannot stop the turn it started.

- Enter sends, Shift+Enter is a new line. While the agent works a send is queued; the queue shows above the box and its cross takes a message back into the box (`Take back`), so nothing is thrown away. A held queue says why and `Send now` lets it go.
- `/` at the start lists the agent's own commands (`SessionView.commands`); `@` lists files and folders of the session's folder over the caret, and pictures can be pasted or dropped: all of it is `design/composer.md`.
- Escape stops the turn only from the box, while a turn runs and no list or dialog wants it.
- Files: `+` opens the system file dialog or the machine's folder (`AttachPicker`), or drop files on the tab. The agent reads paths on its own machine, so a file of this computer for a remote session is first sent (`Send a file`).
- What was typed survives a refusal: it comes back with the reason. A message the agent refused comes back by itself.
- Off, the box says why (`Opening the session…`, `Session ended: …`, `Not connected…`).

## The inspector

`SessionInspector`, a right region of a chat read from a terminal agent that runs subagents or background tasks: what it runs beside the conversation, to consult, not to read. Beside the chat at 320 pt (400 while a subagent's conversation is open); under `snug()` it lies over the chat's right edge instead of squeezing it. Open or closed is one choice for the whole run (`inspectorOpen`), toggled by the header's `Activity` button and `mod+shift+i` (bound by the chat in front); it never closes by itself and opens by itself only for `Needs you`. A chat with nothing beside it has no inspector and no button.

- **Three sections, the state said once in the heading**, never on a row: `Needs you` (a failure that arrived while the chat was open; one already over when the chat first showed it is history, `seedAcknowledged`; `Clear` files them, opening one does too), `Running` (each row: the name, one muted line, the time it has run when the log gives a start, the stop square where there is a way), and `Finished` folded to one muted line `Finished 26 · last 35 min ago` that opens to rows grouped by name (`pnpm build ×2`), newest first. Success is silence: only a failure has a mark (the red cross) and a stopped row the word `Stopped`.
- **A row's words.** A subagent: its name; under it its latest tools while it runs (omp gives them), else the first sentence of what it was asked (`firstSentence`); the agent type only in the tooltip, the whole prompt only in its conversation. A task: the command as the chat's lines say it (`commandSubject`: `pnpm test --watch`, not `cd /x && pnpm test --watch`), its whole command in the tooltip. A subagent started in the background is one row, not a subagent and a task (`SubagentRow.task`).
- **Times come from the log's clock** (`startedMs`, `endedMs`), at most a minute fine (`4m`, `1h 12m`, `35 min ago`); a row without them shows none, never an invented one. The clock moves once a minute while a timed row runs and the tab is in front, else never.
- **Stop** (`Sessions.stopBackground`) asks the agent in its own words for its stop tool (Claude `TaskStop`, omp `proc://<id>/kill`, Codex `wait` with terminate), typed into the pane as the person would and refused like a message; only a running task whose agent offers that way has the square. One that has run a minute or more takes a second press within 4 s; the first turns the square red and the row says `Press stop again to stop it`. A subagent that is not in the background has no stop: there is no route.
- **A subagent's conversation** opens in the inspector (`SubagentChat`), with `Back` (and Escape while no field has the keyboard): its name and state once, its own log read with the parent's mapper (the whole assignment is its first message) in the chat's own transcript, and one line `Read only. Messages go to <parent>, which relays them.` No message box: a subagent is steered through its parent, and the core refuses every send, stop and answer for it. Why the inspector and not a tab: the supervisor consults a subagent without leaving the lead's conversation, and a tab would need the tab strip to name a subagent (it would read `Chat`). It reads only while shown; at most two are open per chat and they close with it. A transcript not written yet is an empty `Waiting for the subagent to write its transcript`, not a failure.
- **Accessibility.** The region is named `Activity`, the list `Subagents and background tasks`, a heading `Running, 4`; a row is `Audit auth module, running 4m, <its line>. Open its conversation`; the stop is `Stop pnpm test --watch`, then `Press again to stop …`; the opened conversation is `Subagent conversation: <name>`. A failure that arrives is said (`Needs you: Check schema drift failed`).

## Accessibility

The conversation is a list named `Conversation`; every row is labelled `You: …`, `Agent: …` (first 200 characters), `Tool: Ran ls, done`, `Thought`, `Subagent: …`. The folded line is a button named by its own sentence (`Read 8 files, ran 4 commands`) with `expanded` (`Disclosure`; a plain `Button` has `selected`, which would read as "selected"); an effect is a group named `Failed: Ran pnpm test, <last line>` or its text, and the edit line a button `Edited 3 files, 12 added, 4 removed. Open changes`. When an agent message finishes its first 200 characters are announced politely, once; streamed text is announced only with `Announce agent output`, at most once per two seconds; a request that arrives is announced (`Needs you: …`) and so is the dock's (`The agent asks: …`). The keyboard goes to the message box when the tab opens and nowhere else by itself (`mod+2` brings it back; with a question showing there is no box and it says so). Status is a shape first everywhere. The sign-in card is told politely when it appears and its title is an `alert`; nsh 0.4.0 has no assertive announcement (`docs/ACCESSIBILITY.md`). Not verifiable headless: announcements (`announce` cannot be read) and the look under a real renderer.
