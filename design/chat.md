# The chat tab

`components/session-tab.tsx` (`SessionTab`) and its parts: `session-header.tsx`, `session-transcript.tsx`, `session-item.tsx`, `session-tool.tsx`, `session-plan.tsx`, `session-inspector.tsx`, `subagent-chat.tsx`, `session-composer.tsx`, `session-queue.tsx`, `session-attach.tsx`, `session-signin.tsx`. The rules are in `lib/session.ts` (data and the model), `lib/session-rows.ts` (turns into rows), `lib/session-text.ts` (words), `lib/session-compose.ts` (the message box), `lib/session-inspector.ts` (the inspector) and `lib/session-pictures.ts`; all pure ones have tests. The answer dock, question form, overview and the mode and model pickers are `design/chat-parts.md`. `session-tab.test.tsx` drives it through `session-lab.tsx`, `session-inspector.test.tsx` through `session-inspector-lab.tsx`.

## What it is

The primary way to work with an agent: a conversation, not a terminal. One tab is either a keeper's ACP session (`id` is the keeper's) or a terminal agent read from its log (`id` is `pane:<paneId>`, with `Show terminal` one press away). The tab opens itself (`Sessions.attach` or `Sessions.observe`) and lets go when it closes; a session that cannot be opened says why and offers `Try again`, and `Continue` for one whose agent exited and kept its conversation. Top to bottom: `SessionHeader` (one `TopBar` line: `title · project · branch`; the title is a button that opens the session's facts in a popover, `Session details`; under a tab strip the front tab says the title, so the line drops it and a `...` at its end opens the facts (`design/tabs.md`); then `Changes` (unless that folder's Changes tab is in the same group), `Open beside` and, for a terminal agent with the terminal tab on (`terminalEnabled`, off by default: `design/pane.md`), `Show terminal`; no state word and no mark, because the sidebar row and the dock say it; the project is the board row's, the branch the last read of git), a banner when the connection is lost (`Reconnect`), one quiet muted line while a copy of the conversation saved on this computer is on screen and the keeper has not yet answered (`Showing the conversation saved at 10:42. Updating…`; `cachedAt`, gone when the replay is whole, and the box says `Opening the session…` meanwhile, so nothing is sent or answered against a copy), one quiet line while the inspector is closed and something runs beside the agent (`ActivityLine`), `SessionPlan`, the conversation, the open request (`AnswerDock` or `SessionQuestion`) and `SessionComposer`, which stands aside while the request shows and comes back, draft kept (`design/chat-parts.md`, "Where it stands").

## The conversation reads like a chat

- **You** are a rounded bubble on the right. Pictures in your message are a row of 72 pt thumbnails under the words (`components/turn-pictures.tsx`), fetched once when the row is drawn (`lib/session-pictures.ts`, cap 16 MiB, at most 8 kept) and shown in place of the agent's own `[Image #n]` placeholders (`withoutPlaceholders`; the placeholders stay when more are named than came); a press opens the lightbox; too large, gone or let go of is a tile of the same height (`Picture too large to show`, `Try again`, `Load`), so the row never changes height. The person's words are plain text, as typed, as herdr-mobile keeps them: Markdown would eat the `*` of a glob, a `<Tag>` and single line breaks. A "you" that is an agent (a subagent's assignment and what its parent relays, `RowContext.fromAgent`) wrote Markdown, so its bubble draws it with `MarkdownText`: lists, code, emphasis, links. **The agent** is Markdown on the page, never a bubble (`MarkdownText`: lists, tables, links and pictures as "Links and pictures" below says, and every fence a `CodeBlock`; prose is `text-base` (14 at 1.55), a table is a hairline under each row with no fill or side lines (`TABLE_CLASSES`): highlighted, its language in the corner, `Copy code`, folded past 16 lines; `design/code.md`). Nothing is cut; an agent message is one selectable area (a drag crosses paragraphs, lists, code and tables, in the recycled list cell too), and every finished message has `Copy message`, which copies its whole Markdown. `copyReply` (`mod+shift+y`) copies the last answer and `copyCode` (`mod+shift+c`) the block under the pointer or else the last one of it, from anywhere in the tab, the message box included. A host that dies when a chat is replaced or closed is the allocator preloaded into the process, not the text view: `preload_guard` (`docs/upstream/nsh-selectable-textview-in-list.md`); the `chat-swap` scenario of `make shots` fails if the host dies again.
- **Files in your message** (`messageFiles` in `lib/message-files.ts`, drawn by `MessageFiles`): a terminal chat sends a file as `@path` in the words (`forTerminal`) and a keeper echoes its attachments as `@name` and `[Image #1] name` lines beside its parts, so under the words a picture is a 72 pt square tile (`PictureTile`, the cache and the finding of `lib/chat-pictures.ts`) and any other file a chip with its glyph and name, and the tokens leave the words: the trailing run goes; when a token also stands inside a sentence, every one is left as its name so the sentence still reads. A press opens it in the side panel. The bubble's name keeps the files: `You: not well aligned. Picture image-4.png`. herdr-mobile shows a message's pictures and file links under its words the same way, but sends a picture to a terminal agent as a pasted path the agent turns into `[Image #1]`; this app still sends `@path`.
- **A turn is ranked by consequence, not time.** Always visible: a pending question (the dock), the final answer, and under it the **effects row** (`EffectsRow`, row kind `effects`, after the turn's last item and only once the turn is over): failures that stand first (the call and the last line it printed, in the warning colour, never an exit code the agent did not send; a failure the agent ran again is not one, see **A failure the agent got past** below), then what happened outside the working tree (`ToolItem.effect`: a glyph by kind and the text, `Pushed to origin/main`), then `Edited 3 files +12 −4`, a button that opens the Changes tab of the session's folder on the files that turn edited (`openChanges` with `edited`; the header's Changes button opens it on everything). Why: the supervisor asks "what did it do" and "can I trust it", and a read-only step must never compete with a push. Everything else (reads, searches, commands, thoughts, and the narration the agent wrote between two calls) is one *group* folded to one muted line (`Read 8 files, ran 4 commands, edited 3 files`: zero counts left out, sentence case, no full stop, never a time); only the turn's last message stays on the page. A press opens the steps, one line each (a failed step also shows its last line in the warning colour); the folded line itself only expands. A path in the final message opens the file in the side panel (`openLink`). The group is folded while its turn runs too: the live line says what happens. The person's own choice of open or folded wins, kept by row key. The pure rules are `lib/session-rows.ts` (`buildRows`, tests in `lib/session-rows.test.ts`); the effects of a turn are carried from group to group (`TurnCarry`), so streaming rebuilds the last unit and never reads the turn again.
- **No state is repeated in the conversation.** No state word, no centred `Done in 12s`, no timer on a finished turn: the sidebar glyph already says it, and a finished turn is its final answer. While the agent works, one muted live line at the bottom says what it is doing now and how long that step has run, and goes when the turn ends (`Footer` in `session-transcript.tsx`, `model.working()`): `Running pnpm test · 12s`, `Editing lib/ask.ts`, `Reading 3 files`, `Thinking · 1m 04s` when no call is open (`liveLine`, `clockText`), and `Quiet for 2m` after it once nothing has arrived for a minute. The clock counts the step the line names, as herdr-mobile's status line does: a call from when this window saw it start, `Thinking` from the turn's start or the last call's end, ticking once a second on the model's clock, which exists only while a turn runs. Times come from what this window watched: a step that began before the chat was looked at has no clock, because inventing one is lying. The half ring turns an eighth at a time (`liveTurn`: one turn in 2 s on the shared ticker) while the agent is heard from and the tab is in front, and stands still once `Quiet for` shows, while a request waits for the person and under reduced motion: moving means "heard from lately", so it never moves for an agent gone silent. Why it may move when the sidebar's working glyph may not (`design/tabs.md`): it exists only in the chat in front, only while its turn runs, at 4 frames a second, where the sidebar would hold one per working agent all day. Why: a still `Thinking` read as stuck (owner, 2026-11-09).
- **The steps between two of the agent's sentences are one hairline card, a step is a row of it, and a box inside means text you can copy** (owner, 2026-11-09, this app beside the Claude desktop app: "typical agent scene, a bit annoying; Claude is cleaner", then "I don't like it, like Claude better"). The calls between two of the agent's words are one step; the steps between two of its sentences are one row (`Row` kind `steps`, `StepsCard`, `StepBlock`; a thought splits steps, not the card), because a box cannot be cut across the list's rows. A row is what the step was for in the agent's own words (`ToolItem.intent`: omp's `i`, Claude Code's `description`; past tense once it is over, `pastTense` and `stepWords` in `lib/session-text.ts`), else the command as before (`Ran make test`), then `and 2 more` when the step had several calls, `· 1 retried` where it applies, then a chevron. A step with a failure that stands is named by that call. Titles are the size of the prose, muted by colour, and start at the card's padding; the marks are at the row's right end: the size of its edits (`+6 −2`), the half ring with the clock and `Quiet for 3m` while a call runs, the alert for a failure that stands. While a call runs, its last two output lines sit under the row (a peek, not an unfold). A press opens the step: a thought before it as a muted line, then each call, the command whole in one flat code block, white with a hairline and no grey surface (always for a command: the row says what it was for, not what it ran), the way it ended (`Exit code 2`, in the warning tone) under the command and above what it printed, an edit as a diff, and the output as plain mono lines that scroll inside themselves past 24 lines (a test run or a build log is read there; owner, 2026-11-10), from the end for a command and from the top for a read (`lines not kept` where the machine dropped some). Spacing carries the hierarchy of an opened step: 8 pt between the step's line and its card, 20 pt between its calls, 8 pt between a call's own title (`text-sm font-medium`, second call on) and its command, 12 pt between the command, how it ended and the output. A step that stands alone between two sentences is a plain line with no card, as in the Claude app; opened, its details are a card under it. The folded group line and the live footer are the same size, so a folded turn reads as the same stream.
- **A subagent stands outside the fold** as its own bordered line (`SubagentRow`; a call of kind `task`, `subagent` or `agent`, or omp's launcher, kind `other` titled `Spawning <name> subagent`, once it carries `ToolItem.progress`: `isSubagent`), because what it hands back is a result, not a step. A terminal agent's subagents and background tasks are the inspector's (below).
- **A `task` call says how its subagents do.** omp sends, with every update of the call, one object per subagent (`rawOutput.details.progress[]`: Rust reads it into `ToolItem.progress`, at most 16, `native/core/src/session/vendored/acp/update.rs`); before the first one the launch's own `rawInput.tasks[]` stands in as waiting subagents, and a turn the keeper trimmed has none. While any subagent works the card shows one quiet line for each under its header, always in view and never behind the chevron (`SubagentLines`, `lib/session-subagents.ts`): a mark (the half ring working, the dashed ring waiting, a check done, a red alert failed, a cross stopped), its name, the tool it is in in muted text (`Reading src/auth.ts`; once it is done the last tool it ran, `Read src/auth.ts`), and `12 tools · 1m 4s` in tabular figures. When all are done the lines fold behind the card's chevron and the header says, muted, `3 subagents, 2m 10s` (the longest time, with `1 failed` or `1 stopped` when it happened). A line's name is the launch's `tasks[].name` found by the progress's `id`, else by its `index` (its place in the list when omp sends none), else omp's `id`. Times are what omp last reported, not a clock of ours, so no line ticks and the card draws nothing between two updates; lines appear and change at once (rows of a live conversation never move, `design/motion.md`). Each line is one labelled element, `Subagent audit, running, Reading src/auth.ts, 12 tools, 1m 4s`, and the card's own label adds the summary. `rowPt` counts 24 pt for each line (`subagentLinesPt`). Claude Code's subagents (grouped by `parentToolUseId`) and Codex's are not drawn by this.
- **A thought** belongs to the step after it and shows only inside that step once it is open (`Thought for 12s ›`, `Row.thoughts`); one with no step after it is not drawn, and while the agent thinks the live line says `Thinking`.
- **Notices** are quiet centred lines for the app's own notes (`Earlier messages are no longer kept`). A failed call is not a notice: a failure that stands is a line under the answer, in the failure colour, because it must not be folded away.
- **A pane herdr could not restore** (`restore_error`, `FeedState::Unrestored`) has no chat and no terminal: its tab is the `Not running` card (`components/not-running.tsx`), herdr's own reason as one safe line (no bidi controls, no newline) and `Close pane` (the palette's `closePane`, which asks first). The engine reads nothing from it (`read_screen`, `read_preview`) until herdr runs it again. Mirrors herdr-mobile's pane screen for the same case; the sidebar and board rows do not say it yet.
- **A failure the agent got past is a count, not an alarm** (owner, 2026-11-09, from the phone: "agents know how to recover, a lot of red is stress"; mobile has the same rule). A failed call is `retried` when a later call in the same work group is the same kind on the same subject (the command, the file), whatever came of it (`retriedIn` in `lib/session-rows.ts`). A retried call is counted on its step's line (`· 1 retried`), the group's line says `Ran 4 commands, edited 1 file · 2 retried` (`workLine`, `WorkSummary.retried`), and it is not in the effects row. In a chain of failed tries only the last stands. A call with an effect outside the machine (`ToolItem.effect`: a push, a delete) is never retried: it stays a line. A retry that is a different command, or in another work group, does not count, so the rule errs towards showing. A step with a failure that stands is named `failed` for a screen reader. Prototyped against four variants (rows only, count only, one quiet line, both), rendered in `chat-retried`.
- **Earlier messages of a terminal's chat** (`observed.earlier`: `none`, `available`, `loading`, `tooLong`). A chat opens at the end of the agent's log (the last 192 KB); the top of the list is `EarlierRow`. `available` is one ghost `Load earlier messages` button; the person who scrolls within one viewport of the top (or whose list is empty) gets it pressed once per arrival (`createAutoLoad` in `lib/earlier.ts`). `Sessions.loadEarlier` returns at once: Rust reads the log again from its end with a tail 4x wider (up to 64 MB) beside the rows shown, and replaces them in one step when the read is whole, so while it runs the rows stay and the row is one `Loading earlier messages…` line of the same height. Rows keep their `id` and the older ones take smaller ones, so the list holds its place and older rows arrive above those in view (key every row by `id`; never by position). `tooLong` is one muted sentence and no button. Why: the log is the truth and a long chat is days of work; the first read must be fast and the rest on request, never a spinner over the whole chat.
- Text from an agent goes through `visibleText`: direction overrides and control characters become `‹U+202E›`, because a command written backwards reads as another command.
- A kind of row the app does not know is a quiet generic line, never a crash.

## Links and pictures

Owner decision of 2026-11-09, picked from a rendered prototype ("handle file and web links so I can check them; a web page is better in a side panel; minimal web links; I expect to see images"). The rules are `lib/links.ts` (`chatMarkdown`, pure, tested), the pictures `lib/chat-pictures.ts` and `components/chat-picture.tsx` (`ChatPicture`).

- **A picture of the session's machine is a thumbnail**: a path relative to the folder or absolute, found as a pressed link is (`Files.find`), read through the file viewer's own reads off the UI thread (`Files.stat`, `Files.open`: over ssh for another machine). At most 280 pt wide, aspect kept, a hairline and `rounded-md`, a muted line under it: `shot-1.png · 640 × 400`. Its box is held while it loads, at the size its header states (`pictureDimensions`) or 160 x 100, with nothing spinning. Kept by where it was named, the last 12, so a re-render does not fetch again. Over 8 MB (`THUMB_CAP`) it is the chip `Image: name · too large to show`. A press opens it large in the side panel.
- **A web picture is never fetched**: the chat does not phone out. It is a chip `Image: <alt>` that opens its address in the panel.
- **A picture only named** in the agent's words (inline code or a link to an image path) gets its thumbnail under its paragraph, drawn only when found. Not in a list, a quote or a table: an image added there would cut the list in two.
- **Links as written.** A link shows its whole text, nothing hidden or highlighted (owner, 2026-11-09, on the short form that showed the host and muted the path: "no need to hide some link part, full link, no special highlight"). A link without a title gets its address as one, so its tooltip and accessible name say where it goes; a title the author wrote stays; code is never rewritten. Links are in the text colour with the text view's light underline.
- **A press opens the side panel** (`design/files.md`, "The side panel"), never the browser by default: an https page, this computer's `localhost` and a remote machine's `localhost` through its tunnel in the embedded browser (`Browser`: back, forward, reload, an address to type, the page takes clicks and typing), a file at its line, a picture. `mod` held over the text (read from the pointer's last move: `TextView` reports no keys) is the old way: the browser or the file's tab. Plain http to another host still goes to the browser.
- **A relative path is found, never refused**: in the session's folder and the two above it, then its checkout and project (`searchFolders`); `./` and `../` from the folder only; `:line` kept. The same for a path in a tool call (its files and edits open in the side panel too) and in your own message. A miss says `.scratch/x.png isn't in <folder>`.

## Signing in

An agent can refuse a session until the person signs in (`SessionView.phase` is `authRequired`, `acp.auth` lists the ways). `SessionSignin` then stands in for the conversation, the request docks and the message box, under the same header: a calm full-width card, `<Agent> needs you to sign in`, and one block per way the agent offers.

- **A way the app carries out** is a button named as the agent names it, with the agent's description under it. It calls `Sessions.authenticate` (through the port, `SessionPort.authenticate`); while the agent decides the button is busy and the others wait. When the agent accepts, the session opens and the card goes.
- **A way done in a terminal** (`terminalArgs`) shows the arguments the agent gave, quoted for a shell (`shellLine`) in a `CodeBlock`, `Copy command` and `I did it, try again` (`Sessions.reopen`). The app never runs it, and nothing opens a browser or a terminal by itself. The agent's message does not carry its program name, so the line is the arguments only and the card says to start the agent's program with them.
- **A refusal or failure** is the agent's own words under the buttons, which stay; `I did it, try again` that finds the agent still asking says so. What was said lives in `createSignin` (per chat), because the card is gone while the agent reopens the session and comes back if it still wants a sign-in.
- The keyboard goes to the first button once, when the tab is in front, and back to a button that was busy when the answer arrives.
- **Not here:** a way that needs a URL (`AuthMethodView` has no URL: the card never invents one), and `Sign out` (`AcpView.canLogout` is exposed, the `Sessions` module has no logout call).

## Following the end

The list is bottom aligned and virtual: only the rows near the window exist, each reads its row and keeps no state (what is open lives in the model, by row key). It follows the end while the person is at the end (64 pt counts as at it). Scrolled away it holds still and a pill says what is new: `3 new messages`, `Needs you` while a request waits, else `Jump to latest`. The pill exists only while scrolled up: at the end it would point at where the person already is. Sending a message jumps to the end. PageUp and PageDown scroll a page from anywhere in the tab (also from the message box), Home and End when no text box has the focus. There is no `j`/`k`. Streaming rebuilds the last unit only (`createSessionModel` builds the rows before it once), so a 5,000-row conversation opens at its end and streams without a layout jump.

## The message box

A rounded card in two tiers (`design/composer.md`): the words on top (pictures, chips, the field, which is one line at rest and grows with the text, and an alert or the typed command's arguments when there is one), then one row of controls inside the card: `+` (attach), the mode chip and model picker (`session-config.tsx`), and one round button at the right. Nothing hangs under the card. The keys live in the keyboard sheet, and where a message goes while the agent works is the placeholder (`Queue a message`), never a note. The `/` and `@` lists open as the card's own top. The button is `Send`, `Queue message` while the agent works, and `Stop` while a turn runs with nothing typed: a muted ring, not a filled button, because then nothing needs the person; its tooltip names `Esc`. A Stop that just appeared ignores presses for 400 ms so the second press of a double press on Send cannot stop the turn it started.

- Enter sends, Shift+Enter is a new line. While the agent works a send is queued; the queue shows above the box and its cross takes a message back into the box (`Take back`), so nothing is thrown away. A held queue says why and `Send now` lets it go. A queue is kept as long as its connection is: a session with messages waiting is never closed for lingering or for room (`SessionHub::reap`, `evict_lingering`), and when the connection drops the messages (and a prompt the agent never showed it had received) are held with `The connection dropped` and carried into the session the next `attach` opens, where `Send now` lets them go. They live in memory only: quitting the app loses them.
- `/` at the start lists the agent's own commands and skills (`SessionView.commands`, skills under their own heading); `@` lists files and folders of the session's folder, and pictures can be pasted or dropped: all of it is `design/composer.md`. A chat read from a terminal is sent words only: a picture saved into the project and an outside file go as their `@path` in the words (`forTerminal`), as herdr-mobile does.
- Escape stops the turn only from the box, while a turn runs and no list or dialog wants it.
- Files: `+` opens the system file dialog or the machine's folder (`AttachPicker`), or drop files on the tab. The agent reads paths on its own machine, so a file of this computer for a remote session is first sent (`Send a file`).
- What was typed survives a refusal: it comes back with the reason. A message the agent refused comes back by itself.
- Off, the box says why (`Opening the session…`, `Session ended: …`, `Not connected…`).

## The inspector

`SessionInspector`, a right region of a chat read from a terminal agent that runs subagents or background tasks: what it runs beside the conversation, to consult, not to read. Beside the chat at 320 pt (400 while a subagent's conversation is open); under `snug()` it lies over the chat's right edge instead of squeezing it. Open or closed is one choice for the whole run (`inspectorOpen`), toggled by the header's `Activity` button and `mod+shift+i` (bound by the chat in front); it never closes by itself and opens by itself only for `Needs you`. A chat with nothing beside it has no inspector and no button.

- **Three sections, the state said once in the heading**, never on a row: `Needs you` (a failure that arrived while the chat was open; one already over when the chat first showed it is history, `seedAcknowledged`; `Clear` files them, opening one does too), `Running` (each row: the name, one muted line, the time it has run when the log gives a start, the stop square where there is a way), and `Finished` folded to one muted line `Finished 26 · last 35 min ago` that opens to rows grouped by name (`pnpm build ×2`), newest first. Success is silence: only a failure has a mark (the red cross) and a stopped row the word `Stopped`.
- **A row's words.** A subagent: its name; under it its latest tools while it runs (omp gives them), else the first sentence of what it was asked (`firstSentence`); the agent type only in the tooltip, the whole prompt only in its conversation. A task: the command as the chat's lines say it (`commandSubject`: `pnpm test --watch`, not `cd /x && pnpm test --watch`), its whole command in the tooltip. A subagent started in the background is one row, not a subagent and a task (`SubagentRow.task`).
- **Times come from the log's clock** (`startedMs`, `endedMs`), at most a minute fine (`4m`, `1h 12m`, `35 min ago`); a row without them shows none, never an invented one. The clock moves once a minute while a timed row runs and the tab is in front, else never.
- **Stop** (`Sessions.stopBackground`) asks the agent in its own words for its stop tool (Claude `TaskStop`, omp `proc://<id>/kill`, Codex `wait` with terminate), typed into the pane as the person would and refused like a message; only a running task whose agent offers that way has the square. One that has run a minute or more takes a second press within 4 s; the first turns the square red and the row says `Press stop again to stop it`. A subagent that is not in the background has no stop: there is no route.
- **A subagent's conversation** opens in the inspector (`SubagentChat`), with `Back` (and Escape while no field has the keyboard): its name and state once, its own log read with the parent's mapper (the whole assignment is its first message, drawn as Markdown in its bubble) in the chat's own transcript, and one line `Read only. Messages go to <parent>, which relays them.` No message box: a subagent is steered through its parent, and the core refuses every send, stop and answer for it. Why the inspector and not a tab: the supervisor consults a subagent without leaving the lead's conversation, and a tab would need the tab strip to name a subagent (it would read `Chat`). It reads only while shown; at most two are open per chat and they close with it. A transcript not written yet is an empty `Waiting for the subagent to write its transcript`, not a failure.
- **Accessibility.** The region is named `Activity`, the list `Subagents and background tasks`, a heading `Running, 4`; a row is `Audit auth module, running 4m, <its line>. Open its conversation`; the stop is `Stop pnpm test --watch`, then `Press again to stop …`; the opened conversation is `Subagent conversation: <name>`. A failure that arrives is said (`Needs you: Check schema drift failed`).

## Accessibility

The conversation is a list named `Conversation`; every row is labelled `You: …`, `Agent: …` (first 200 characters), `Steps` (the card, a group) holding `Step: Ran ls and 1 more` (`, running` or `, failed` when it is, `, 1 retried` after a failure the agent got past), `Thought` (inside an open step), `Subagent: …`. The folded line is a button named by its own sentence (`Read 8 files, ran 4 commands`) with `expanded` (`Disclosure`; a plain `Button` has `selected`, which would read as "selected"); an effect is a group named `Failed: Ran pnpm test, <last line>` or its text, and the edit line a button `Edited 3 files, 12 added, 4 removed. Open changes`. When an agent message finishes its first 200 characters are announced politely, once; streamed text is announced only with `Announce agent output`, at most once per two seconds; a request that arrives is announced (`Needs you: …`) and so is the dock's (`The agent asks: …`). The keyboard goes to the message box when the tab opens and nowhere else by itself (`mod+2` brings it back; with a question showing there is no box and it says so). Status is a shape first everywhere. The sign-in card is told politely when it appears and its title is an `alert`; nsh 0.4.0 has no assertive announcement (`docs/ACCESSIBILITY.md`). Not verifiable headless: announcements (`announce` cannot be read) and the look under a real renderer.
