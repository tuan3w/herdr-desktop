# Files, viewers, diagrams and pages

`components/files.tsx` (`FilesTab`: the browser, with `FileViewer` in `file-viewer.tsx`), `design/media.md` (the player and every other viewer), `markdown.tsx` (`Markdown`), `mermaid-block.tsx` (`MermaidBlock`), `link-panel.tsx` (`LinkPanelView`, the side panel), `send-files.tsx` (`SendFiles`). The state and rules are `lib/files.ts` and `lib/mermaid.ts` (pure, with tests); the work is Rust (`herdr_core::files`, the `Files`, `Pages` and `Diagrams` modules). `files.test.tsx` and `pane-files.test.tsx` drive it against `fixtures/files/project`, a synthetic folder the test seam (`Files.testTree`) copies; the shots and the audit use the same folder through `files-lab.tsx`.

## What it is for

The question while supervising is "what did it just touch?". Everything here is **read only** except `Send a file`, and nothing here is a second editor: no typing into a file, no save. Doors in, all through `browseFiles` and `viewFile` (`lib/open-files.ts`): the pane's `Browse files`, the palette entry `Browse files…`, and a path pressed in a pane, in Markdown, in a tool call or in the person's own message (`openLink`). A relative path is never refused for its shape: it is found on the session's machine in its folder and the two above it, then in the checkout and the project that folder belongs to (`searchFolders`, `Files.find` over `find_path`, the tries ordered as `candidates` orders them); `./x` and `../x` are the session's folder's only, as herdr-mobile looks them up; a miss says `<path> isn't in <folder>`.

## The Files tab (built)

`FilesTab` (`components/files.tsx`) is a tab of the dock, `files:<machine>/<folder>` (`filesKey` in `lib/dock.ts`), opened the way Changes is: a tab of the group, with a folder glyph on its project tile, titled `Files · <folder>`. Why a tab and not the dialog the owner called ugly (2026-11-08): a dialog hid the conversation and any question waiting in it, and "what did it touch" is consulted for minutes. Every door goes through `browseFiles` and `viewFile` (`lib/open-files.ts`): the terminal header's `Browse files`, the palette, quick open, a path in a pane or in Markdown, a file named by a tool call or a chat chip, Send's folder. A tab for that folder that is already open is shown and told where to go; `requests` holds what each tab was last asked.

- **Header, one line**: `Up one folder`, the folder as a breadcrumb that is the path (`FilesTrail`: a pressable segment each, a chevron between, the last one is the folder shown and is not pressable, the middle collapses into a `…` menu when the path is wider than the room, `fitTrail` in `components/files-trail.tsx` measures the names as drawn, so the collapse is in points, never a character guess; the trail asks for root, `…` and the current folder before the search field, which gives way first), `Find in this folder` and `Folder options` (sort by, hidden files, the preview). The path is shown once: the empty room after the crumbs, or `mod+l`, turns it into the `FolderField` (completion of folders on the machine, Enter goes, Escape returns to the crumbs).
- **A table, not a list of sentences**: kit `Table` with Name (takes the room, ellipsis only past the row), Size and Modified (fixed widths, right-aligned, tabular figures: digits start at the same x in every row, measured on three rows of different name length in the macOS render), and a `…` of the row (copy path, send to the agent, open with the system, reveal). Folders first whatever the sort. A press on a title sorts it (the table cycles ascending, descending, default); the same choice is in `Folder options` for the keyboard, with size and date starting from the largest and newest. Narrow, Modified leaves first, then Size. 32 pt rows, one fill for hover and the highlighted row.
- **Keys**: the table has the keyboard once a folder shows. Up and Down move, Enter opens (a folder enters, a file opens in the viewer in place of the table, a picture in the lightbox), Backspace and `mod+up` go up, a letter starts the filter, `/` focuses it, Space or `mod+y` previews beside the table, `mod+l` edits the path. Escape leaves the viewer, then the path field, then the preview; it never closes the tab. The headless runner does not deliver Escape or the arrows inside the lightbox to shortcuts, so those are unverified in tests (the Back and Close buttons are tested).
- **States, in words, in place of the table**: a folder that cannot be opened says why (and for a denial that the person may not read it) with `Try again` and `Up one folder`; empty says `This folder is empty`, a filter with no hit `No file matches`; while a folder loads the old list stays, dimmed, and the first load is skeleton rows, never a spinner. A folder listed earlier in this run (`lib/folder-cache.ts`, memory only, 64 folders) shows its rows at once with its own `N min ago`; the machine's answer replaces them only when something differs (`sameListing`), so the selection stays, and a failed read leaves them and says why. One muted line under the table: `6 items · 1 hidden`, and in words the cut at 5000 entries and the names that are not text.
- **Not built**: a right-click menu on a row (the table's context event is not wired; the `…` is), the sort remembered between runs (it is kept between tabs and openings), the viewer filling the tab's height (its body is a fixed 400 pt block inside a scroll), a changed-first view.

## One language for listing files

Every list of files draws its rows from `components/file-row.tsx`: `FileName` (the glyph of `fileGlyph` in `lib/files.ts`, one set by kind: folder, image, film, music, archive, terminal, sliders, list, file; the whole name; a muted folder after it only in a search result, never in one folder's own listing), `FileSize` and `FileModified` (the fixed right-aligned columns) and `FileRow` (a 32 pt row of them for lists that are not tables). Used by the Files tab (table cells), the attach list (`session-attach.tsx`) and the `@` list (`composer-picker.tsx`); quick open takes the glyph and keeps the palette's own row, which also draws agents and commands; the folder field's suggestions are the kit autocomplete's rows. The Changes list keeps its own row (status letter and `+12 −3`).

## The viewer

`FileViewer`: `Back to the folder`, name, `812 KB · 4 min ago · devbox`, then by kind (`ViewKind`, decided by the core from the name and the first bytes):

- **Text**: a `CodeBlock` (`design/code.md`) with the language its name says, line numbers fixed on, and for a link that names a line (`main.rs:12`) that line marked and scrolled to (`goTo`, `CodeView.goToLine`). It selects and copies, and `mod+f` opens `PaneFind` over the file's lines (Enter and Shift+Enter step, the current line is marked and brought into view); it never changes the file, and is named `<file>, read only`. Decided with evidence: the `Editor` was kept for the one thing the view cannot do, a file of any size: above 512 KB (`CODE_VIEW_LIMIT`) the viewer is the read-only `Editor`, whose own find and caret keys then apply, because the code view builds a row per line.
- **Markdown**: `Markdown` with a `Preview`/`Source` switch (`Source` is the editor).
- **Everything else** (pictures, video and sound, PDF, archives, tables, JSON, big text, binaries): `design/media.md`.
- `Reveal` and `Open` act on a file of this computer only (`reveal_path`, `open_path`: Rust-only in nsh 0.4.0, so no `fs` capability is needed); `Copy path` works everywhere. A file that changes on disk is not followed: go back and open it again.

## Pictures

A picture opens in the lightbox (`components/lightbox-view.tsx`, rules in `lib/lightbox.ts`), not as a step of the Files tab: a dimmed window, the picture fitted with an 8% margin, the name line `name · 3 of 12` (the count only with more than one picture) at the top left, `...` (Send to the agent, Copy image, Copy path, Open, Reveal, Rotate) and `Close` at the top right, nothing else at rest. The controls fade after 2 s of stillness (they stay under reduced motion and while the menu is open); the 40 pt arrows show only under the pointer at an edge; `Left` and `Right` walk the folder (and stop at its ends), `+`, `-`, `0`, `1` and `R` zoom in 25% steps and turn; the wheel zooms smoothly (`wheelZoom`, continuous, not steps) toward the point under the pointer (`zoomAt`); a double click toggles fit and actual size, a drag pans, the zoom readout shows for 1.2 s after a zoom and the level is announced once it settles. The picture is drawn once at its own size and zoomed by a `scale()` transform, never laid out again at a new size: that re-layout made zooming a large photo lag (owner, 2026-11-08). The picture is never inside the scroll view that hears the wheel: a scroll is drawn the frame it happens, before the zoom arrives, so a picture inside jumped along every notch and back, which read as zooming in and out (owner, 2026-11-09). `Escape` returns to the folder with the row kept. A remote picture is copied once into the cache (`files_cache`, emptied at start) up to `IMAGE_CAP` (40 MB). The window is given the picture as a `data:image/...;base64,` address read in Rust off the UI thread (`FileData.image`, mime from the first bytes), never a `file://` address: the packaged app cannot grant one to an image (`docs/DEVELOPMENT.md`, nsh host quirks). Over 16 MiB (`PICTURE_DATA_CAP`, the string lives in the JS heap) the viewer says `This picture is too large to show here (N MB). Open or Reveal it.`

## Markdown and diagrams

`Markdown` is nsh's `TextView` (selectable, tables, task lists) with its fences drawn by `CodeBlock`; its links and pictures follow `design/chat.md` ("Links and pictures"): a path opens found like a pane link, a picture of the machine is a thumbnail, a web picture is never fetched.

**Diagrams are drawn.** A closed ` ```mermaid ` fence is a custom node (`extensions`) shown by `MermaidBlock`: the bundled mermaid in a web view, no network. Decided with evidence (the GTK shot and the AT-SPI tree of the `file-diagram` scenario), because the plan allowed the fallback of a code block:

- The web view is in the accessibility tree as `grouping 'Diagram: sequence diagram'` holding `document web` holding `image 'Diagram: sequence diagram'` (the page's own `role="img"` and `aria-label`). It is named, and one Tab stop at most (the page has nothing focusable, so Tab moves on).
- The **text alternative is the source**: `Show source` toggles it under the diagram (an `Editor`, read only, copyable), and the label above is a heading `Diagram: <title>` (`diagramTitle`: front-matter title, a `title` line, else the kind). `Open diagram` shows it larger in a dialog.
- A source mermaid cannot draw stays text with one line saying why (`Couldn't draw this diagram · … · showing the source`): a wrong diagram never replaces readable text.
- **No network.** The page's policy (`diagramPage`) is `default-src 'none'` with the one script origin and inline script and style, `securityLevel: "strict"`; the source reaches the page as escaped text, never as script (`mermaid.test.ts` has the injection test). The script (`assets/mermaid.min.js`, 11.12.0, MIT, `NOTICE`) is served once from a loopback listener of this process (`Diagrams.origin`: `GET /mermaid.min.js` and nothing else, `127.0.0.1` only) because a web view may load `http` addresses of the hosts `nsh.json` lists and not `file:` ones; the web view's cache then serves every later diagram.
- Cost: one web view per diagram on screen (they exist only while a document with diagrams is open). A diagram taller than 360 pt scrolls inside its frame; `Open diagram` gives 480.

## Send a file

Files dropped on a pane tab (`onFileDrop`, shown by a dashed `Drop to send to <machine>: <folder>` while dragging) open `SendFiles`: the folder (the pane's, editable, must be a folder on the machine) and `Send`. **Nothing is sent before `Send`.** A name that is already there is never overwritten: that file's row says `A file with this name is already there` and offers `Replace` or `Skip`. Rows show `4 KB of 12 MB` with a bar, `Stop` while running, and say what happened; a stopped or failed upload leaves nothing behind (the data goes to a hidden `.name.herdr-part` next to the destination and moves with an atomic link only when whole). Only files from this computer are accepted (`Files.pathFromUri`); anything else is refused with a sentence. Folders are not sent.

## The side panel (pages, files and pictures a link opens)

`LinkPanelView` (`components/link-panel.tsx`, state `lib/link-panel.ts`): what a pressed link of a chat or a terminal points at, in the right region beside it (460 pt, `LINK_PANEL_WIDTH`; under `snug()` it lies over the content's right edge, as the inspector decision says), so the conversation and a question waiting in it stay in view. Owner decision of 2026-11-09 ("a web page is better in a side panel"), replacing the page dialog and, for links, the file viewer's tab and the browser. One panel per chat or terminal, replaced by the next link; while it is open it takes the inspector's place, which comes back when it closes. Nothing of it is remembered across tabs or launches.

- **Header** (a file or a picture): one `BAR`-high line like the chat's: the kind's glyph, the title (the file name and `:line`; the picture's name), then muted where it is (the folder, the picture's pixel size and folder), which stays in view while the title gives way. The title's tooltip and accessible name carry the whole path. `Copy link`, `Open as a tab` (the old place, the panel closes), `Close` (Escape while the pointer is over the panel, or while no text field has the keyboard; never in a terminal, whose program owns Escape).
- **A page** is the embedded browser, `Browser` (`components/browser.tsx`, rules `lib/browser.ts`), reusable anywhere a page is shown. Its toolbar is the panel's one line (owner, 2026-11-09: "a proper embedded browser, not just for displaying"): `Back`, `Forward`, `Reload` (`Stop loading` while it loads), the address, `Copy link`, `Open in browser`, `Close`; disabled controls stay, muted. The address shows the host in the text colour and the rest muted (`addressParts`; `http://` stays written, a user name is never shown as the host), with `<machine> · through ssh` after it for a tunnelled page; focused it is the whole address. Enter goes: text without a scheme is https (http for this computer's loopback), and plain http to another computer, other schemes and words are refused with what to do (`webAddress`): it never searches. While a page loads a 2 pt line runs over its top edge (the kit's `Progress`), never a spinner. The person clicks, types and scrolls in the page (WebKit takes the pointer and keys natively). Keys while the pointer is over it or the address has the keyboard (in a terminal, only the latter): `mod+l` the address, `mod+[` and `mod+]` back and forward (only when they can act, else the app's own), `mod+r` reload, Escape gives the keyboard back to the message box (`focusComposer`); `Close` closes. A failure covers the page: `Couldn't load github.com`, the reason, `Try again`, `Open in browser`; `Back` from it returns to the page under it.
- **What may load**: the address field and `routeLink` take https and loopback http; inside a page nsh decides every navigation natively from `capabilities.webview` (http and https of any host, frames too on Linux: nsh matches hosts, not schemes, so a page's own link to plain http does load), so a `mailto:`, `file:` or app link is refused and says so once (`refusedNote`), the page staying. A link or `window.open` asking for a new window opens in place (`PAGE_SCRIPT`: nsh has no second window, the link would do nothing). Nothing is downloaded: no `onDownload` listener, so WebKitGTK ignores what it cannot show (a download link does nothing; `Open in browser` does it). A sound or video that starts without a press in the second before is paused. A remote machine's `localhost` is reached through `Pages.open`: a free port of `127.0.0.1` forwarded to the machine's port over its shared ssh connection (`ssh -O forward`, loopback only), made when the panel shows it and removed (`-O cancel`) when it closes or shows something else; the browser shows, copies and takes typed addresses as the machine's (`swapOrigin`) and `Open in browser` hands over the tunnelled address, which works while the panel shows it.
- **A file**: `FileViewer` itself with `panelHeight`: the content alone at the panel's height, the line a link named marked and scrolled to, the view switch kept, nothing playing and no global keys taken from the chat.
- **A picture**: fitted (`ImageView`); over the thumbnail cap it says so and offers its tab.
- `mod` held at the press is the old way: the browser, or the file's tab. A surface without a panel (the Files tab's Markdown) opens links the old way, and a remote `localhost` there is copied with a sentence, since only a panel holds a tunnel.

## Machines other than this one

`RemoteFiles` runs `fs.py` (`ls`, `stat`, `read`, `put`, `commit`, `discard`) through the machine's `SshClient`, so no new login and no SFTP stack; it needs `python3` on the machine and says so when it is missing. Every path is validated (`validate_path`: absolute or `~/`, no NUL, at most 4096 bytes) and travels as one argument that the generated command quotes with `shq`; `files.rs` tests run hostile names (`$(…)`, backticks, newlines, `; touch`) through the real quoting and find nothing executed.
