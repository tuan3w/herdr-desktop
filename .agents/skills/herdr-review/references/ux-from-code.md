# UI/UX, read from code

`herdr-design` decides what a screen should be; this file only says how to find problems in a diff without rendering it. Every row you produce from it is "from code, not seen" until `herdr-screen-check` has rendered it (say on which platform).

1. **Find the journey step and the region.** Which of the five questions does the changed UI serve (needs me, alive, what did it do, steer, trust)? Which region (sidebar, main, inspector, status) is it in, and is that region's job respected? Open `herdr-design/references/journeys.md` for the surfaces that share the concept. Serves none: a noise candidate. An agent listed a second time in a view: a finding.
2. **Never / Instead sweep, changed files only.** Candidates, not findings; confirm each in context. The static gates first: `nsh check`, `node_modules/.bin/oxlint --deny-warnings`, `node scripts/absolute-imports.mjs --check`. Then greps over the changed files:
   - `grep -nE "#[0-9a-fA-F]{3,8}\b|rgb\(|oklch\(|text-[a-z-]+/[0-9]" <files>`: raw colour, or alpha on a text colour (an unknown class: use `opacity-*`).
   - `grep -nE "ring-|box-shadow|shadow-\[" <files>`: ring classes draw nothing; focus is `FOCUS_RING*`.
   - `grep -nE "transition|duration-|ease-|Animated\.|createMotion|setTimeout" <files>`: motion outside `lib/motion.ts` belongs to `herdr-motion`; list the hits and hand off.
   - `grep -nE "alt\+|escape|keymap\.bind" <files>`: shortcuts live in `lib/shortcuts.ts`, with `mod`, never `alt`, never global `Escape`.
   - `grep -nE "\bh-[0-9]+\b|height:" <files>`: a fixed height clips at `fontScale()` 2.0; rows are `min-h` (`ROW`).
   - `grep -nE "\.\./|from \"\./" <files>` outside `components/kit/`: project imports are `#lib/`, `#components/`, `#kit`.
   - `grep -nE "text-signal|IconName|variant=" <files>`: the closed lists in `DESIGN.md`.
   - 36 pt controls beside 32 pt fields (the leftover list in `AGENTS.md`): check any file in it that the change touches.
3. **State coverage.** For each screen or row touched, find the branch for: first paint, live, stale machine, offline machine, failed, empty, one, many (a virtual `List`), needs-you, working, done, collapsed project, narrow window (`compact()`, `rail()`, `narrow()`, `snug()`). A state with no branch is a finding. Unavailable things stay, dimmed, with their reason. A failure says what happened and what to do.
4. **Honesty.** A value shown without its freshness; a stale machine drawn as live; "running" where "was running" is true; liveness inferred from a timer instead of from herdr; an invented field. Status is a shape, then a word, then colour, never colour alone.
5. **Said once.** Count the marks one fact gets in the view after the change (row mark, tab dot, header word, status count, footer line). `text-signal` is used by nothing but the chat's `New output` pill; a new use is a design change. A project header shows a count only while folded.
6. **Guard proportion.** Cheap and reversible: a click. A slip: `notify(..., { undo })`. Irreversible: `confirmDestructive`. Risky answer: two-step (4 s), shown whole. Bulk: confirm built from live data. Check `GUARD_MS` (400 ms) on anything that appears under the pointer; check that the command being approved is shown whole.
7. **Keyboard and names.** Every control has a name (`IconButton` needs `label`; `Field` sets `accessibilityLabel`; a glyph is never a name; the name has no role word). State is `accessibilityState`, not a darker fill. Focus visible. A key path exists, is in `lib/shortcuts.ts`, shows in the tooltip (`keyLabel`), and the palette lists it. Popups keep focus on the trigger and move a highlight.
8. **Parity table.** When the changed concept appears on more than one surface (sidebar row, Board row, rail tile, answer dock, bulk answer, palette, switcher, notification), build the table `herdr-design` describes, each cell from that surface's own code. An empty or differing cell is a finding unless a reason is written down.
9. **Words.** Sentence case, outcome first, numbers, correct plurals, no apology, recovery stated. Cut text: `Clipped` (hover shows it all) where the person does not need it, never on a command, a name that tells rows apart or an error. Paths cut in the middle.
10. **Persistence.** What survives a project switch, a restart and a reconnect (layouts `herdr.dock.v2`, chat scroll `herdr.views.v1`, drafts in memory only)? Does Settings or a page still leave a waiting question visible?
11. **Docs move with code.** A UI change updates the screen's `design/*.md`; `design/attention.md` and `design/board.md` carry cutover notes. `make docs` fails on a backticked name that does not exist.
12. **Hand off.** List what only pixels or the real app can settle (overflow at 760 and `fontScale()` 2.0, contrast, edge alignment, focus order, motion, feel) and name the skill: `herdr-screen-check`, `herdr-critic`, `herdr-motion`. Mark each row "from code, not seen". On macOS add "no Linux render, no `make a11y`".
