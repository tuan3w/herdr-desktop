# Bug classes in herdr-desktop

A prompt for where to look, not a list of findings. An item here is a finding only when you can name the input that breaks *this* code. "Seen here" is real history taken from `AGENTS.md` and `docs/DEVELOPMENT.md`, so you know the shape.

| Class | Ask of the code | Seen here |
|---|---|---|
| Guards and approval | Can anything be approved silently, by default, on a timeout or by a notification? Does the person see the command whole? Does the answer path re-read the pane and refuse when the question changed? Is a risky answer two-step (press, press again within 4 s), never a timed hold? | The rules are tested in `components/answer-dock.test.tsx`; a new answer surface (Board bulk, notification action) must repeat them from its own code, not from the shared component |
| Stale or offline shown as live | What does a stale or offline machine's row, count or answer do? Is it counted as waiting, answerable, or drawn without the dashed glyph? | A machine not connected lists its agents dimmed and `offline` and never counts them as waiting |
| Event payloads | Does a handler treat the whole event object as the value? In nsh 0.4.0 events take one object (`onChange({ value })`, `onExpandedChange({ expanded })`, `keymap.bind(k, ({ keystroke }) => ...)`). | `onExpandedChange={(expanded) => expanded ? pause() : resume()}` type-checks (truthiness) and always paused the toasts |
| The gap after an `await` or a revision | After each await or a `revision N` re-pull: is the pane, tab or row still there, and is the answer still for this question? | A press resolved while the engine's pane reads landed aimed at a row replaced a moment later |
| UI-thread cost | Parsing, ssh, sockets or decoding in TSX or in an event; a list that mounts every row (`Each` over thousands); allocation per row on a hot path. Sockets, ssh, parsing and ACP belong to `herdr-core` threads; TSX is told "revision N" and pulls with synchronous module calls (principle 5). | Mounting every row costs memory and CPU by the row; a long list is a virtualized `List` whose row reads its item as an accessor and keeps no state |
| Lifecycle and cost | Who stops this timer, subscription, listener, retry, `ssh` child or keeper? Does back-off reset only after real progress? Does a loop exist only while on screen (`If`, `cleanup`)? Does an app at rest draw no frames? | A loop keeps the app drawing every frame for as long as an agent works: the working glyph is not an endless turn |
| Data boundaries | Empty, one, many, huge; a title with diacritics, CJK or RTL; unbounded text (herdr bounds nothing); a char cut by a chunk boundary; rounding at a unit edge; relative times at a step edge. | Debug with `references/worst-case.md` of `herdr-screen-check` |
| Failure semantics | Is a wire error classified fatal (stop retrying, show `Attention`) or retryable (principle 8)? Is success reported when the last step failed? A swallowed rejection? | `Storage` is one 5 MB quota for all keys: a write over it rejects (`lib/save.ts` turns it into a warning); `Clipboard.writeText` without `"clipboard": true` in `nsh.json` only logs and the app believes it copied |
| Remote shell and injection | Is anything typed into a remote shell validated or single-quoted (`shq()` in `native/core/src/ssh`)? Does a destination follow `--`? Is there an injection test? Is a secret on a command line, in a log or a fixture? | Ssh identities stay with ssh; the app uses the system `ssh` (ControlMaster) and a small python relay |
| Protocol facts | Does a method name, field or status come from `docs/herdr-api.schema.json` (refreshed by `make schema`) or from memory? Does it touch herdr's private client socket (forbidden)? | A mutating method with empty params against the live herdr creates a tab |
| One connection per machine | Does a fault in one machine touch another? Two code paths opening a second connection? | Principle 7; a reconcile exception that stops every machine is the shape to look for |
| Shortcuts and focus | Is a global shortcut without `mod`, with `alt`, `Escape`, `mod+q` or `F11`? Does it steal typing (Telex, VNI, AltGr)? Is it in `lib/shortcuts.ts` once? Does a view take focus from code (it cannot: only inputs)? | `lib/shortcuts.test.ts` enforces the rules; `App.test.tsx` presses every global shortcut as macOS, Windows and Linux |
| Identity and ordering | Is a row identified by position or recycled-cell order? Does `app.texts()` order or an array index stand for identity? | `app.texts()` of a list is in the order its recycled cells were made, not screen order: read an order from `Herdr.board()` |
| Typed work | Does a draft survive a failed send, a project switch, a reconnect? (Drafts are memory only, by design: a draft can hold a pasted secret.) | `lib/view-state.ts` |
| Notifications and alerts | Can an alert be dropped, doubled or delayed by a cooldown or a flap? Is a platform that cannot do buttons (macOS `osascript`) handled? | `docs/ALERTS.md`, `docs/MACOS.md` |
| Platform splits | `cfg(target_os)` code, `mod` as Cmd vs Ctrl, `/proc` vs `proc_pidinfo`, socket path length (103 bytes on macOS), the Linux-only preload guard. A Linux-green test says nothing about the Mac window. | `docs/MACOS.md`, "What differs from Linux" |
| Native widget lifetime | Destroying a native widget (a tab swapped, a closed tab) with a preloaded allocator can abort the host; never work around it in components. | `native/app/src/preload_guard.rs`, `docs/upstream/nsh-selectable-textview-in-list.md` |

## Three habits

- **Read the consumers.** For a new status, fixture name, setting or wire field, read every switch and filter that sees it. The value that lands in a default branch is the bug.
- **Look at the shape of the interleaving.** A race finding is numbered steps, not an adjective: "1. the board shows; 2. the engine's `pane.read` answers; 3. the row the press resolved is replaced; 4. the handler never runs".
- **Look for the twin.** The same job done a second way is where the fix was missed (sidebar vs Board, dock vs bulk answer, popover vs menu).
